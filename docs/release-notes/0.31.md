## Fixed

**Make shorter, Expand, More formal, More casual and To English now actually rewrite your text.**

They were returning it unchanged. The fault wasn't the actions — it was the engine underneath them.

Glide's on-device model is `Qwen3.5-2B-Base`, a *base* model rather than an instruction-tuned one.
Asked in plain language to "rewrite this to be shorter", it hands back exactly what it was given.
Measured against the shipped model, four of five register-and-length actions echoed their input
verbatim every single time.

The app already knew this about its own model — the inline grammar pass is prompted with worked
examples for precisely this reason — but 0.30 shipped nine new instruction-following actions on top
of an engine that cannot follow instructions.

Those actions now carry worked examples and are prompted the same way the grammar pass is. Measured
on the same model and the same inputs afterwards:

- "I am writing to let you know that the deployment we discussed has been postponed until further
  notice." → **shorter:** "The deployment has been postponed." · **casual:** "We're holding off on the
  deployment for now."
- "hey can you send me that file when you get a chance" → **formal:** "Please send me the file when
  you have a moment."

**Expand is still weak on already-long sentences** and will often decline to change them. That is a
limit of a 2B model, not a bug; a cloud engine handles it fine.

**And an action that changes nothing now says so.** Previously, an engine echoing your text back was
indistinguishable from the action silently failing — Glide replaced the selection with itself and
reported success. It now tells you "No change suggested" and leaves the text alone. Copy and the
preview actions are exempt, since returning the selection verbatim is what they are for.

See ADR-138.
