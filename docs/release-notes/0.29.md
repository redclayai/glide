## Fixed

**Polish and Grammar now actually apply their result in web-based apps.**

0.28 fixed the Polish button so it fires. This fixes what happens next.

The selection toolbar wrote its result through the Accessibility API and trusted the API's answer.
Chromium reports that write as successful and then silently discards it — so in Millie, Claude
Desktop, Slack and Teams, Glide believed it had replaced your text, and the clipboard fallback that
would have actually done the job never ran. Both buttons appeared to do nothing.

Glide now waits to see the field's value actually change before believing the write, and pastes the
result instead when it doesn't. The wait is a poll rather than a single check, because a Chromium
field takes around 75ms to publish the change — checking once and immediately would mistake a
successful write for a failed one and insert the text twice.

Same underlying defect as ADR-133, in the one code path that had its own copy of it.
