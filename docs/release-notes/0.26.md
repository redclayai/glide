## Fixed

**Suggestions no longer paint over selected text.**

Selecting a sentence could leave a second copy of it drawn on top of the first, most visibly in
web-based editors. The text was never actually duplicated — Glide was drawing an autocomplete
suggestion on top of it.

The cause: when text is selected, macOS reports the cursor as sitting at the *start* of the
selection. Glide took that at face value, generated a completion for everything before it, and drew
the ghost text at the anchor — directly over the line the user had just selected. In a web editor,
where the caret rectangle for a selection resolves to the start of the line, the two copies landed
almost on top of each other.

Glide now suppresses completions entirely while text is selected. That was always the right
behaviour independent of the drawing bug: the next keystroke replaces a selection rather than
extending it, so there is nothing there to complete.

This supersedes the 0.25 fix, which addressed the wrong mechanism — see ADR-132.
